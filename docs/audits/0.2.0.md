What the main fixes mean for someone using the library:

- A saved layout is no longer erased when it cannot be read once, when it comes from a newer version, or when the app goes back to the previous release candidate (reliability X1, X2).
- One panel whose content crashes no longer blanks the whole workspace; it shows a "could not load" state with a retry (reliability X3).
- The README's install command works, and installs the release instead of a release candidate (usability H1, H2).
- A fullscreen panel can be left by touch or mouse, and a panel can be moved or closed with a single tap or click (usability H3, M1; accessibility H2).
- Keyboard focus is visible on the library's buttons, and the sharing pieces no longer crash under the library's own theme (accessibility H1, H3).

## Open items

Waiting for a decision by the project owner:

- Whether a panel should shrink to fit a window narrower than 390 px by default. Today it is cut off at the edges (accessibility M6).
- Whether every slide should be instant under the system's reduced-motion setting. Today only the closing panel is (accessibility M7).
- Whether a QR value that is too long should show a "too long" box. Today it draws an empty tile.
- Whether each source file should carry the MPL header. Today the notice is given once in the README (licenses M3).
- Whether the release check should also build and inspect the package tarball.

Decided by the owner: the package is published by hand, not by an automated pipeline (security M7).

Open, with no decision recorded. None of these blocks the release:

- **Sharing sheet.** Warning texts are below the 4.5:1 contrast minimum in the light theme, one control shows no focus indicator, focus is lost after some actions, right-to-left layout is incomplete, and the sheet cannot show that an action is under way, worked or failed (accessibility H1 leftover, M1, M3, M8; usability M4, M5).
- **Saved state.** Two saves that arrive out of order can leave the older one in place (reliability X4). One malformed entry in a saved workspace means nothing is restored from it, though the file is no longer overwritten (X5). After a load fails, nothing is saved for the rest of that launch and the person is told only if the app shows the error (new in the fix).
- **Input limits.** A very large number in a saved split record can freeze the first layout for some seconds (security M1), with four more Medium security findings left as they were (M2, M3, M5, M8).
- **Other.** The side-by-side divider has no single-pointer route to a given split (accessibility H2 leftover). Undo after a close still needs the keyboard user to reach the button within 10 seconds (M4). A few upgrade notes and README lines are out of date (usability M8).

The package does not meet WCAG 2.2 AA in full, and the release should not claim that it does.

## Not covered

No real phone or tablet, no Safari or Firefox, no real screen reader, and no real browser storage were used: tests ran in Node and in headless Chromium. Apps built with the library, and the three apps that already use it, were not audited; each of those apps needs a one-line change of its own before it benefits from the saved-state fix. Findings of level Low and Note were re-checked only where a fix touched them.

The seven detailed re-check reports, with file and line evidence for every status above, accompany this report.
